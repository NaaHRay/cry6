About the problemChapter 01

No single request looks dangerous. Together, they are.

  1. 01

    Data ends up in logs

    Names, emails and account numbers get written to logs in plain text. Anyone who can read the logs can read the data.

  2. 02

    Hashes can be guessed

    Hash a phone number without a secret key, and an attacker can try every number until one matches.

  3. 03

    Exposure adds up

    Each request reveals a little. Across many requests, the same customer becomes identifiable.

Judged one at a time, these requests look fine. The first is allowed and the next three only get masked.

The gateway remembers what this customer has already exposed. Added together, the score reaches high risk and the decision changes to TOKENIZE. These scores are from the cumulative exposure attack in the test reports.

R(t) = αS(t) + βC(t) + γL(t) + δD(t)

S
How sensitive this payload is
C
How much of this customer has already been exposed
L
How easily the identifiers can be linked together
D
How risky the destination is
About the gatewayChapter 02

One request. Nine steps.

  1. Input normalizationThe request is parsed into a form every later step can read.{ "email": "rohan.gupta@example.in", "account_number": "123456789012" }
  2. Sensitive data detectionAnchored patterns and validators look for PAN, Aadhaar, IFSC, UPI and more.EMAIL rohan.gupta@example.in ACCOUNT_NUMBER 123456789012
  3. Sensitivity classificationThe payload gets a class from S0 (harmless) to S4 (most sensitive).class S3
  4. Purpose classificationWhy is this data moving? One of 8 purposes.PAYMENT_PROCESSING
  5. Exposure scoringThis request is scored together with what the customer has already exposed.R(t) = αS(t) + βC(t) + γL(t) + δD(t)
  6. Policy decisionEach value gets an action: allow, mask, tokenize, encrypt or block.ENCRYPT
  7. Cryptographic protectionKeys are derived per tenant and purpose. AES-256-GCM, HMAC or masking is applied.AES-256-GCM with a fresh 96-bit nonce
  8. Protected outputThe service downstream receives this instead of the original.{ "email": "[ENCRYPTED:AES256GCM_…]", "account_number": "[ENCRYPTED:AES256GCM_…]" }
  9. Audit recordTypes and decisions are recorded in a hash chain. Original values are not.H(i) = HMAC-SHA-256( key, H(i-1) || event )
